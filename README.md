**Результат:** Recall@50 = **0.92** на валидации, **0.89** на лидерборде.

## Подход

1. **Кандидаты** (~280 на запрос) внутри гео-пула запроса (та же локация или ближе 50 км) из трёх источников:
   - топ BM25 по леммам заголовка, параметров и описания;
   - топ BM25 по всему корпусу;
   - топ по косинусу дообученного энкодера `multilingual-e5-base`.
2. **Признаки** для каждой пары «запрос — кандидат».
3. **Ранжирование** CatBoost (YetiRank) → топ-50 в `answer.csv`.

## Данные и признаки

Train раскладываю на уникальные запросы (текст + локация + категория + фильтры) и пары «запрос → выбранное объявление».
Тексты объявлений нормализую: для BM25 — леммы (pymorphy3), для энкодера — мягкая чистка без лемматизации.

| Группа | Признаки | Зачем |
|---|---|---|
| BM25 | скоры по заголовку, параметрам, описанию; ранги кандидата в выдаче | основной текстовый сигнал |
| Совпадение слов | доля слов запроса в заголовке и во всём объявлении | отличает полное совпадение от случайного |
| Энкодер | косинус запроса с полным текстом и с заголовком | синонимы и разные формулировки, которые не видит BM25 |
| Гео | расстояние до центра локации поиска, совпадение локации | услуги локальные: 83% выборов из той же локации |
| Фильтры | выполнение фильтров поиска | у 97% выбранных объявлений фильтр запроса выполняется |
| Микрокатегория | вероятность микрокатегории кандидата по тексту запроса | текст определяет микрокатегорию выбора в 86% случаев |
| Объявление | рейтинг, отзывы, цена, длины полей | слабые, но полезные для ранжирования сигналы |

## Модели

- **BM25** — своя реализация на разреженных матрицах (SciPy).
- **Энкодер** `intfloat/multilingual-e5-base`, дообучен в два раунда: сначала с in-batch негативами, затем с hard-negatives, собранными из того же гео-пула.
- **Классификатор микрокатегорий** — TF-IDF (слова, символьные n-граммы, фильтр) + логистическая регрессия (SGD).
- **CatBoost** с ранжирующим лоссом YetiRank выбирает итоговый топ-50.

## Проверка качества

- **Валидация:** 3000 запросов из train, чьи выбранные объявления есть в корпусе бенчмарка. Поиск — по настоящему корпусу. Разбиение по тексту запроса: тексты val полностью исключены из обучения.
- **Метрики:** Recall@50 по формуле задания (в знаменателе все релевантные, включая не попавшие в кандидаты) и потолок кандидатов.
- **Защита от утечек:** предсказания классификатора для обучающих запросов CatBoost считаются out-of-fold, энкодер эти запросы при обучении не видел.
- **Формат `answer.csv`** проверяется автоматически перед сохранением.

## Найденные ошибки и что сделал

| Проблема | Что сделал | Эффект |
|---|---|---|
| Флаг «удалённая услуга» по тексту срабатывал слишком широко и раздувал гео-пул до половины корпуса | убрал из пула, оставил признаком | BM25@50 на val: 0.64 → 0.83 |
| Разбор фильтров по ключам «Вид/Тип услуги» ломался на других ключах («Какими комнатами занимаетесь…») | проверка, что фильтр целиком покрывается кусками текста параметров объявления | корректная проверка фильтров |
| 17% запросов бенчмарка из «региональных» локаций без своих объявлений: строгий фильтр по локации дал бы 0 | координаты локации оцениваю по выборам в train, фильтрую по радиусу | кандидаты есть у всех запросов |
| ~5% правильных ответов в гео-пуле, но BM25 не находит их по словам | добавил энкодер как источник кандидатов и признак | потолок 0.93 → 0.97, Recall@50 0.89 → 0.92 |
| Val выше лидерборда (0.92 против 0.885) | проверил гипотезы: «энкодер запомнил объявления» не подтвердилась, часть разрыва объясняет смещение val к объявлениям с большим числом отзывов, запросы с категорией 0 почти не встречаются в train | улучшения меньше ~0.01 на val считаю ненадёжными |
| Гео-признаки «куда из этой локации ходят» и относительные признаки внутри запроса: +0.008 на val, но хуже на лидерборде | откатил | финальная версия без них |

## Воспроизведение
